# MiniEval — A ready-to-use LLM evaluation library

MiniEval evaluates a target LLM on a built-in general-purpose dataset. The user does **not** need to find, upload, or prepare a dataset. The target LLM can be a Python callable supplied by the developer or an installed Ollama model. Ollama currently provides the judge model. MiniEval runs all four metrics automatically and returns a report object.

## What users do

1. Install Python 3.11+ and Ollama for the judge.
2. Install at least one judge model manually (`ollama pull llama3.2` is an example, not run automatically by MiniEval).
3. Install MiniEval.
4. Pass your LLM as a Python function, or choose an installed Ollama target model.
5. Review the per-question and aggregate reports, then export JSON/CSV.

No cloud services, API keys, database, vector store, or model training are required.

## Built-in dataset

The included dataset is `minieval/data/general_eval.csv`. It contains 12 curated questions spanning general knowledge, science, simple arithmetic, context-based QA, computer science, security, and logical reasoning. Each item includes an expected answer and context, so all four metrics can run after the target model generates its answer.

This is a small starter evaluation set, not a standardized benchmark. For meaningful comparisons, expand the dataset and keep the same dataset, threshold, and judge configuration between model runs.


If `python` is not recognized, install Python 3.11+ from https://www.python.org/downloads/windows/ and select **Add Python to PATH**. If PowerShell blocks virtual-environment activation, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` and retry activation.

Ollama must be running and the target/judge models must already be installed. MiniEval never downloads models automatically.

## Quick start: command line

Use the built-in dataset by omitting `--dataset`:

```powershell
python cli.py --target-model llama3.2:latest --judge-model llama3.2:latest
```

Replace model names with the exact names from `ollama list`. If `--judge-model` is omitted, the target model is also used as the judge. Using separate target and judge models is preferable when available.

Results are written to `minieval_results.json` and `minieval_results.csv` by default. Specify another output prefix if desired:

```powershell
python cli.py --target-model llama3.2:latest --judge-model qwen2.5:7b --threshold 0.7 --out reports/run1
```

MiniEval creates the output directory if needed. The optional `--dataset path.csv` argument allows custom CSV, JSON, or JSONL data, but is not required for normal use.

## Use as a Python SDK with your own LLM

The recommended integration is to pass a function that accepts a question string and returns the answer generated by your LLM. Your target model does not need to run through Ollama; Ollama is used as the judge in this version.

```python
from minieval import evaluate

# Replace this body with your own model's inference call.
def my_llm(question: str) -> str:
    return my_chatbot.generate(question)

report = evaluate(
    model=my_llm,
    judge_model="llama3.2:latest",  # an installed Ollama model
    threshold=0.7,
    # dataset is optional; MiniEval's bundled dataset is used by default
)

report.print_summary()
report.print_results()
json_path, csv_path = report.save("evaluation_results")
print(f"Saved: {json_path} and {csv_path}")
```

The callable contract is intentionally simple: `model(question: str) -> str`. MiniEval calls it once for each benchmark question. Exceptions and empty/non-string answers are reported as errors instead of being silently counted as passing results.

### Evaluate an Ollama target instead

```python
from minieval import evaluate

report = evaluate(
    target_model="llama3.2:latest",
    judge_model="llama3.2:latest",
    threshold=0.7,
)
report.print_summary()
report.save("minieval_results")
```

`evaluate()` returns an `EvaluationReport`, which remains dictionary-compatible:

- `report["results"]`: detailed per-question answers, metric scores, statuses, reasons, evidence, and timings.
- `report["summary"]`: mean scores and pass/fail counts for each metric.
- `report.print_summary()` and `report.print_results()`: print human-readable reports.
- `report.save("name")`: write `name.json` and `name.csv` and return both paths.

All applicable metrics run automatically. The SDK does not require users to select metrics or supply a dataset. The built-in dataset is small and intended as a starter benchmark; custom CSV, JSON, and JSONL datasets remain optional.

### Optional custom dataset

CSV/JSON/JSONL rows support `question`, `expected_answer`, `context`, and optional `actual_answer`. If `actual_answer` is provided, MiniEval evaluates that answer; otherwise it asks the target model to generate an answer. Correctness requires `expected_answer`; faithfulness and hallucination risk require `context`.

## Metrics and scoring

| Metric | What it measures | Pass rule | Required data |
|---|---|---|---|
| Answer Correctness | Semantic/factual match with the reference answer | score ≥ threshold | Expected answer |
| Answer Relevance | Whether the response answers the question directly | score ≥ threshold | Question and answer |
| Faithfulness | Support of answer claims by context | score ≥ threshold | Context |
| Hallucination Risk | Unsupported or contradicted claims relative to context | risk ≤ threshold | Context |

Scores range from 0 to 1. Missing required reference data results in N/A rather than an invented score. No single overall score is computed by averaging unlike metrics.

## Limitations

- The built-in dataset is intentionally small and is not a comprehensive or certified benchmark.
- LLM-as-judge results are estimates and can vary by judge model and prompt.
- Using the same model as target and judge can introduce self-evaluation bias.
- Faithfulness and hallucination risk are evaluated relative to supplied context; unsupported does not necessarily mean false.
- The target can be any Python callable that accepts a question and returns a string, or an installed Ollama model. No dedicated adapters for hosted APIs are included; wrap your API call in the callable.
- Ollama is required for the judge in the current version. A future release could add alternative judge backends.
- MiniEval does not retain history in a database.
